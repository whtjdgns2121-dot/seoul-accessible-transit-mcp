## 1. 오프닝 (30초) — 문제 제기

**멘트:**

> "지도 앱은 누구에게나 최단 경로를 알려줍니다. 하지만 휠체어 이용자에게 최단 경로는 종종 **불가능한 경로**입니다. 엘리베이터 한 대가 멈추면 그 역은 통째로 벽이 되니까요. 서울 지하철 엘리베이터 865대 중 지금 이 순간에도 10대 안팎이 멈춰 있습니다. 문제는 — **가보기 전엔 알 수 없다**는 겁니다."

> "'쉬운길 서울'은 이 판단을 AI에게 맡깁니다. 시연으로 보여드리겠습니다."

---

## 2. Act 1 — 킬러 장면: 실시간 고장 감지 + 대안 (2분)

**입력할 질문** (사전 체크에서 확정한 고장 역으로 교체):

```
휠체어 타고 사당역에서 서울역까지 가려는데 엘리베이터 다 이용 가능한지 확인해줘
```

**예상 흐름**: TOOL 호출 박스 표시 → 사당역 엘리베이터 **운행중지** 감지 → 대안 제시 (다른 출구 엘리베이터 / 저상버스 / 콜택시)

**응답이 나오는 동안 멘트:**

> "지금 AI가 저희 MCP를 호출해서 경로상 **모든 역의 엘리베이터 가동 상태를 실시간으로** 확인하고 있습니다. 서울교통공사가 5분마다 갱신하는 공공데이터입니다."

**응답이 뜨면 (하이라이트 순간):**

> "보십시오 — 사당역 6번 출구 엘리베이터가 **지금 실제로 멈춰 있습니다**. 저희가 심어놓은 데모 데이터가 아니라 실시간 장애입니다. 그리고 중요한 건 여기서부터입니다: 사용자가 묻지 않았는데도 AI가 **스스로 대안을 세 가지** 내놓습니다. 같은 역의 정상 엘리베이터, 저상버스 우회, 장애인 콜택시까지. 이게 조회와 에이전트의 차이입니다."

**TOOL 호출 박스를 펼치며:**

> "투명성도 확인하실 수 있습니다. 어떤 도구가 어떤 인자로 호출됐는지 전부 공개됩니다."

---

## 3. Act 2 — 확장 장면: 육아 가정 (1분)

**입력할 질문:**

```
서울역에 기저귀 갈 수 있는 곳 있어? 수유실 위치 알려줘
```

**예상 응답**: 가족수유실 (B1 여자화장실 인접) — 기저귀교환대 1대, 이용시간

**멘트:**

> "교통약자는 휠체어 이용자만이 아닙니다. 유아차를 끄는 부모에게는 수유실과 기저귀교환대가 이동 가능성을 결정합니다. 엘리베이터·수유실·저상버스를 **하나의 대화**에서 해결합니다."

---

## 4. Act 3 — 마무리 장면: 저상버스 실시간 (1분)

**입력할 질문:**

```
서울역버스환승센터에 저상버스 언제 와?
```

**예상 응답**: 저상버스만 필터링된 실시간 도착 목록 (예: "1711번 — 7분 30초 후")

**멘트:**

> "버스도 마찬가지입니다. 일반 도착 안내는 저상·고상을 섞어 보여주지만, 휠체어 이용자에게 고상버스 정보는 소음일 뿐입니다. **탈 수 있는 버스만** 보여줍니다."

---

## 5. 클로징 (30초)

> "정리하면 — '쉬운길 서울'은 서울교통공사·서울시 공공데이터 4종을 MCP로 묶어, AI가 교통약자의 관점에서 **실제로 갈 수 있는지 판단하고, 막히면 대안을 만들어내는** 서비스입니다. 열차 지연·무정차 같은 운행 이례상황도 경로 판정에 함께 반영됩니다. 서울의 교통약자 100만 명이 카카오 AI에게 '갈 수 있어?'라고 물을 수 있게 되는 것 — 그게 저희가 만든 변화입니다."

## 예상 Q&A

**Q. 데이터 출처와 갱신 주기는?**
> 서울교통공사 편의시설위치정보(엘리베이터 매 5분, 공공데이터포털 오픈API), 지하철알림정보(매 1분), 서울시 버스도착정보(실시간), 정류소정보. 전부 공식 오픈API이며 활용신청 승인을 받았습니다.

**Q. 경로 탐색은 왜 직접 안 하나?**
> 의도적 설계입니다. 경로 계획은 지도 AI가 이미 잘하는 일이고, 저희는 **"그 경로가 교통약자에게 실제로 가능한가"라는 검증**에 집중했습니다. 덕분에 다른 지도 MCP와 레고처럼 조합될 수 있습니다 — MCP 생태계 철학에 맞는 구조라고 생각합니다.

**Q. 응답 속도는?**
> 평균 2초 내외, 20초 TTL 캐시와 커넥션 재사용으로 반복 호출은 더 빠릅니다. p99 3초 요건을 충족합니다.

**Q. 서울 외 지역 확장은?**
> 부산·대구 등 지자체 승강기 데이터가 있는 도시로 동일 구조 확장이 가능하고, 전국 저상버스 API는 이미 표준화되어 있습니다.

**Q. 기술 스택은?**
> Python + 공식 MCP SDK(FastMCP), Streamable HTTP, stateless. Render 배포, GitHub Actions로 상시 가동 유지. MCP Inspector 표준 점검을 통과했습니다.
