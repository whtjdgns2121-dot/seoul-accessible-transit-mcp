## 0.5. PlayMCP 제출 요건 (준수 필수) ✅ 확인됨

### 서버
- **Streamable HTTP** 방식만 지원 (SSE-only/stdio 불가)
- **Remote MCP** 서버만 — 공개된 URL(도메인)로 접근 가능해야 함 → **배포 필수**
- **Stateless** 권장 (no session)
- MCP 버전: 최소 `2025-03-26` ~ 최대 `2025-11-25`
- 인증 필요 시 OAuth 또는 커스텀 헤더 방식. (우리 MVP는 **개인정보 인증 불필요** → OAuth 생략 가능)
- 제출 전 **MCP Inspector**로 표준 스펙 사전 점검 필수
- **활발히 운영되는 공식 SDK** 사용

### 이름 규칙 ⚠️
- **서버명/툴명에 "kakao" 사용 금지** (대소문자 무관, prefix/suffix/중간 모두 불가)
- 툴명: 1~128자, `A-Z a-z 0-9 _ -` 만, 중복 불가, **대소문자 구분**
- 카카오가 툴 반영 시 MCP prefix를 자동 부여 → **툴명에 서비스명 넣을 필요 없음**

### 툴 개수
- 최대 20개 금지선, **3~10개 권장** ← 우리는 MVP 2~4개로 안전

### 각 툴 필수 property
- `name`, `description`, `inputSchema`, **`annotations`**
- annotations는 5개 값 **모두** 지정: `title`, `readOnlyHint`, `destructiveHint`, `openWorldHint`, `idempotentHint`

### description 규칙
- **영문 작성 권장**, 1,024자 이내
- **서비스명(고유명사)을 영문+국문 병기로 포함** (예시 형식: `...from Melon(멜론)`)
- 우리 서비스명(예): **`무장애서울(BarrierFreeSeoul)`** ← 확정 필요

### 운영
- 툴 응답속도 평균 **100ms 이내**, p99 **3,000ms** 필수 → 외부 API 느릴 수 있으니 **캐싱/타임아웃** 설계
- result 크기 최소화. error/비-widget 응답은 **정제된 마크다운** 텍스트로 (API 원본 그대로 금지)
- 광고 노출 유도 금지

### 스택 결정 (요건 반영)
Streamable HTTP + Stateless + Remote(공개 URL 배포)가 핵심. **Python FastMCP** 또는 **Node MCP SDK** 둘 다 충족.
→ 최종 선택은 §7 TODO 참고.

## 1. ⭐ check_station_facilities — 승강기 + 수유실/기저귀교환대 실시간 상태 ✅ 구현됨

데모의 심장. 특정 지하철역의 엘리베이터/에스컬레이터가 **지금 정상인지·점검중인지**, 그리고 수유실·기저귀교환대 유무를 반환.

- **데이터명**: `서울교통공사_편의시설위치정보` (data.go.kr **15143841**)
- **제공기관**: 서울교통공사 / **Base URL**: `apis.data.go.kr/B553766/facility`
- **사용 오퍼레이션**:
  - `GET /getFcElvtr` — 엘리베이터/에스컬레이터/휠체어리프트 위치+가동현황, **매 5분 갱신**, JSON 지원
  - `GET /getFcNrsrm` — 수유실 위치+시설정보(기저귀교환대 개수 포함), 매일 갱신
- **주의**: 구버전 데이터셋 `15067770`(→ 종료된 `OA-15994` 연결)은 **사용 금지**. 위 15143841이 2025-06 신규 개방된 정식 API.

### 요청 파라미터 (실측 확정)
| 파라미터 | 설명 |
|---|---|
| `serviceKey` | 인증키 (편의시설위치정보 1건 신청으로 getFcElvtr·getFcNrsrm 등 15개 오퍼레이션 전부 커버) |
| `dataType` | `JSON` (default XML) |
| `stnNm` | 역명 포함검색 (예: "신촌") |
| `numOfRows`, `pageNo` | 페이징 |

### 응답 필드 (실측 확정)
**getFcElvtr**: `vcntEntrcNo`(근접 출입구, 숫자 또는 "2번출구"/"내부" 등 자유텍스트), `dtlPstn`(상세위치), `fcltNm`(시설명 자유텍스트 — 역마다 포맷 다름, 키워드 매칭으로만 유형 분류), `lineNm`, `bgngFlr`/`endFlr`, **`oprtngSitu`**(가동현황 코드: **M=정상, S=운행중지**; 2026-07-11 전수조사 865대 중 M 848·S 16·빈값 1)

**getFcNrsrm**: `dprSwchbrdCnt`(기저귀교환대 개수), `infntBedEn`/`infntBedCnt`(유아용 침대), `utztnHr`(이용시간), `dtlPstn`/`exitNo`(위치), `fcltSeNm`(예: "가족수유실")

### 알아둘 것
- `fcltNm`은 역마다 포맷이 달라("승강기)엘리베이터-신촌 4번..." vs "승강기)엘리베이터_까치산(5)역 2번출구...") 문자열 슬라이싱 대신 **키워드 포함 여부로만 유형 분류**(에스컬레이터/리프트/기본값 엘리베이터).
- `vcntEntrcNo`가 순수 숫자가 아닐 때(예: "내부")는 `dtlPstn`을 함께 붙여 위치를 구분(같은 역에 "내부"가 여러 개 존재).
- 가동상태는 정확한 코드값(M/S) 외에 변형 텍스트에도 견디도록 키워드 기반 판정(`_status_class`)을 병행.

## 2. get_low_floor_bus_arrival — 저상버스 실시간 도착 ✅ 구현됨

정류장 기준, **저상버스만 필터링**한 실시간 도착정보. Act 3 대체경로의 핵심.

- **2단 체인**: 정류소명 → `stId` 변환(`서울특별시_정류소정보조회`, data.go.kr 15000303, `getStationByName`) → 저상버스 도착(`서울특별시_버스도착정보조회`, data.go.kr 15000314, `getLowArrInfoByStId`)
- **포맷**: XML 전용. 공통 응답 구조 `ServiceResult > msgHeader(headerCd 0=정상/4=결과없음) > msgBody > itemList[]`
- **핵심 필드**: `rtNm`(노선명), `arrmsg1`(도착메시지), `stId`/`stNm`/`arsId`(정류소)
- **주의**: 정류소는 정식명칭 필요(예: "서울역환승센터"는 결과없음, "서울역버스환승센터"가 정식명칭). 동일 명칭이 방향별로 여러 개 존재 → 앞쪽 3개 정류소까지 조회 후 중복 제거.
- "운행종료" 메시지는 노이즈로 필터링, 도착예정(숫자 포함 메시지)을 앞으로 정렬.

## 3. verify_route_accessibility — 경로 무장애 검증 + 실시간 운행 알림 ✅ 구현됨

> **설계**: "경로 계획"이 아닌 "경로 검증"으로 설계. 경로 계획은 호출하는 에이전트(카카오 AI/지도 툴)가
> 담당하고, 우리는 **"그 경로가 교통약자에게 지금 실제 가능한가"** 판정에 집중한다.
> 실시간 지하철 운행정보도 **외부 경로 API 없이**, 역 목록에서 파생한 노선 정보로 반영한다
> (완전한 경로계획형 대안은 ODsay/TMAP 의존이 커서 의도적으로 배제 — 2026-07-11 결정).

- **입력**: 경로상 역 목록(순서대로) + 이동유형 (`['화곡','신촌']`, `wheelchair` 등)
- **동작**:
  1. 전 역 승강기 상태 **병렬 조회**(asyncio.gather + 캐시) → 막히는 역 식별
  2. 조회된 역들의 `lineNm`(호선)을 모아 **경로가 지나는 노선 집합**을 구성
  3. `서울교통공사_지하철알림정보`(§4)에서 **그 노선에 걸리는 현재 진행중인 알림**만 필터링해 표시
  4. 막힌 역이 있으면 대안 3단계 제시: 같은 역 다른 출구 → 저상버스 우회(`get_low_floor_bus_arrival`) → 콜택시(`find_call_taxi`)
- **안전 설계**: 정보 없는 역이 있으면 "가능" 판정 대신 **판정 보류**
- 역 개수 상한 10개 (p99 3s 보호)

## 4. 지하철 실시간 운행 알림 (verify_route_accessibility 내장) ✅ 구현됨

열차 지연·사고·무정차·배차조정 등 **실시간 이례상황**을 경로 노선에 매칭해 반영.

- **데이터명**: `서울교통공사_지하철알림정보` (data.go.kr **15144070**)
- **Base URL**: `apis.data.go.kr/B553766/ntce`, `GET /getNtceList`
- **⚠️ 별도 활용신청 필요**: 같은 서울교통공사 제공이지만 편의시설위치정보(15143841)와 **계정이 분리**돼 있어 403 발생 → 이 API만 따로 활용신청해야 함(자동승인, 게이트웨이 반영까지 다소 지연 가능).
- **핵심 필드**: `noftTtl`/`noftCn`(제목/내용), `lineNmLst`(콤마구분 호선), `xcseSitnBgngDt`/`xcseSitnEndDt`(이례상황 시작/종료, ISO 8601 `YYYY-MM-DDTHH:MM:SS`, KST 가정), `nonstopYn`
- **핵심 판단 로직**:
  - `xcseSitnBgngDt`가 **없는** 항목은 정보성/테스트 메시지로 간주해 제외 (실측 데이터에 "우이신설선 메시지 테스트입니다" 같은 다국어 테스트 메시지가 다수 섞여 있음을 확인)
  - `now`가 `[시작, 종료]` 구간 안에 있는(또는 종료가 없는=현재진행형) 것만 "활성"으로 채택
  - 경로의 `route_lines`와 알림의 `lines` 교집합이 있거나, 역명이 알림 본문에 직접 언급되면 매칭
  - 매칭 없으면 "실시간 운행 알림 없음"을 명시적으로 표시(침묵 대신 — 실시간 반영이 실제로 동작했음을 보여주기 위함)
- **타임존 주의**: 서버가 Render 등 UTC 환경에 배포될 수 있으므로 `datetime.now(timezone.utc).astimezone(KST)`로 명시 변환 후 비교.

## 5. find_call_taxi — 장애인 콜택시 fallback ✅ 구현됨

저상버스·경로가 모두 막힐 때 **특별교통수단(장애인 콜택시)** 정보 제공. 정적 안내(연락처·이용조건) 수준으로 MVP 구성, 실시간 배차는 범위 밖.
